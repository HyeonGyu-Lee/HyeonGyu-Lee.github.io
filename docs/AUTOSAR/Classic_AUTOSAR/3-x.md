## 3.x baseline에서 application과 platform의 경계를 이해하는 상황


Classic에서는 SWC, RTE, BSW와 ECU configuration의 관계가 중요하다. Release는 표준 문서 집합의 기준이며 공급사 package와 generator의 버전은 별도다. 기능의 이름과 실제 지원 interface를 구분하면 version 변경의 영향을 구체적으로 설명할 수 있다.


## Classic AUTOSAR 3.x


> Application, RTE, BSW의 역할을 분리하고, ECU별 configuration을 통해 software component와 hardware를 연결하는 Classic AUTOSAR 기준 버전이다.


## 구성과 책임


| 영역                | 역할                                                  |
| ----------------- | --------------------------------------------------- |
| Application       | SWC의 기능과 port interface 정의                          |
| RTE               | SWC 통신과 BSW service 접근 연결                           |
| BSW               | Communication, diagnostic, memory, OS 및 hardware 접근 |
| ECU Configuration | ECU에 필요한 module instance, parameter와 reference 구성   |


## 버전 관리


| 구분              | 관리 대상                           |
| --------------- | ------------------------------- |
| AUTOSAR release | 적용 표준과 schema                   |
| BSW package     | 공급사 module 구현과 지원 범위            |
| MCAL package    | MCU·peripheral별 driver 구현       |
| Generator       | RTE·BSW 설정 입력과 생성 코드의 interface |


표준 release, 공급사 package, generator 버전은 서로 다른 식별자다. ARXML의 definition reference와 schema, 생성 코드의 API는 사용하는 package 조합에 맞아야 한다.


## 이해를 확인하는 질문


> 표준 release가 같으면 공급사 package 간 설정을 그대로 옮길 수 있을까?


Schema와 definition reference, 지원 feature·extension 및 generator contract를 함께 확인해야 한다. 같은 release 표기만으로 설정과 생성 코드의 호환성을 보장할 수 없다.
