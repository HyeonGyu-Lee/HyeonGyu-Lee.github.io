## R20-11의 위치
> 2020년 Adaptive 기준선이다. 이 페이지는 Application과 platform의 실행·통신·저장·software lifecycle 관계를 함께 읽는 관점을 정리한다. 개별 기능의 최초 도입이나 변경된 요구사항은 별도의 release 문서 근거가 필요하다.

## 이 기준선에서 구분해 읽을 내용

| 구분 | 표준의 의미 |
| --- | --- |
| Platform architecture | Application과 functional cluster 사이의 역할 분담 |
| Application interface | Service·data type·ara API 등의 계약 |
| Execution / state | Process lifecycle과 system 상태 책임의 구분 |
| Configuration | Interface 정의와 실제 deployment/machine 연결의 구분 |
| Lifecycle | 지속 data와 software version의 관계 |

위 항목은 문서를 분류하는 관점이며 모두 R20-11에서 신규 도입됐다는 의미가 아니다. 적용 release package에 포함된 문서와 각 cluster의 history를 기준으로 실제 지원 범위를 읽는다.
## 아키텍처 발전의 맥락
Adaptive의 발전은 Classic을 없애는 방향이라기보다, 고성능 ECU에서 application을 독립적으로 구성하고 service와 platform 기능의 계약을 정교하게 기술하는 방향으로 이해할 수 있다. Interface, 상태, 권한과 software lifecycle은 서로 연결되므로 하나의 기능명만으로 release 전체를 설명하기 어렵다.
## 문서 version과 release
같은 release 안에도 각 문서의 version과 revision 이력이 따로 존재한다. SWS의 변경과 explanatory 문서의 설명 보강을 구분해야 한다. 공급사 runtime의 feature 추가는 AUTOSAR 표준의 신규 도입과 같은 사건이 아닐 수 있다.
## 확정된 변경 이력을 위한 근거
Release Overview와 해당 functional cluster의 document change history, 이전/현재 요구사항 ID를 함께 대조해야 변경 이유와 범위를 확정할 수 있다. 현재 페이지에는 공식 원문 대조 없이 추정한 연도별 신규 기능 목록을 두지 않는다.
