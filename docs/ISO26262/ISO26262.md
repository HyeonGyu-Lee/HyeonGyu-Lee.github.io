## 개념과 검증 관점 보강 · 2026-10-12


문서 성격: 기술 학습 정리. 작성자의 실무 수행·성과를 의미하지 않습니다. 예시는 설명용이며 실제 시스템 사양이 아닙니다. 규범적 판단은 적용 표준의 판·릴리스와 프로젝트 사양을 확인해야 합니다.


### 핵심 요약


ISO 26262는 도로 차량의 전기·전자 시스템에서 오작동으로 발생하는 위험을 다루는 기능 안전 표준이다. 품질 전반, 사이버보안, 의도된 기능의 성능 한계를 모두 하나의 표준으로 포괄한다고 해석하지 않는다.


### 적용 기준


ISO 26262:2018 시리즈를 찾아 읽기 위한 개념 안내다. 실제 적용에는 제품 범위, 표준의 해당 부, 적용 판과 조직 안전 계획을 확인한다. 프로젝트에서 적용하거나 인증받았다는 의미는 아니다.


### 안전 요구사항의 흐름


아이템 정의 → 위험 분석 및 리스크 평가(HARA) → 안전 목표 → 기능 안전 개념 → 기술 안전 개념 → 시스템·하드웨어·소프트웨어 개발과 검증으로 연결한다.


ASIL은 위험 시나리오의 심각도, 노출도, 제어 가능성을 바탕으로 결정한다. 개발자가 임의의 점수로 숙련도를 표시하거나 제품 전체에 하나의 등급을 붙이는 식으로 사용하지 않는다.


### 개발 시 확인할 질문

- 어떤 오작동과 위험 시나리오를 다루는가?
- 안전 요구사항이 어떤 안전 목표에 연결되는가?
- 안전 메커니즘이 어떤 고장을 탐지하거나 제어하는가?
- 검증 결과가 요구사항 충족을 어떻게 보여주는가?
- 변경으로 인해 안전 분석·설계·테스트에 어떤 영향이 생기는가?

### 진단 문서와 연결


DTC를 저장하거나 NRC를 반환한다는 사실만으로 기능 안전 요구사항을 충족했다고 볼 수 없다. 고장 탐지 범위, 반응 시간, 상태 전이, 안전 요구사항과의 연결을 별도로 검토한다.


### 설명용 검증 구성


안전 요구사항 ID, 시험 조건, 고장 주입 방식, 기대 반응, 판정 기준, 실행 결과를 연결한다. 실제 안전 주장에는 독립성·검토·분석 등 적용 표준에서 요구하는 활동과 근거가 추가로 필요하다.


### 다른 활동과의 관계


Automotive SPICE는 개발 프로세스 관점에서, ISO 26262는 기능 안전 관점에서 함께 고려할 수 있다. 어느 한쪽의 수행만으로 다른 쪽의 준수를 자동 입증하지 않는다.
