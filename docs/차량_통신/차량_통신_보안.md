## 핵심 요약


통신 오류 검출, 인증·기밀성, 진단 접근과 시스템 위협 분석의 차이를 정리한다.


## 적용 범위


네트워크 구성과 시험 조건을 함께 기록하고, 적용 규격·장비·도구 버전을 확인한다.


## 본문


### 보호 목적


무결성, 인증, 기밀성, 가용성은 다른 목적이다. CAN·Ethernet CRC는 우발적 오류 검출이며 암호학적 인증을 대체하지 않는다.


### 보호 계층


TLS는 적용 transport·세션의 보호를, MACsec은 Ethernet 링크 계층 보호를 고려한다. AUTOSAR SecOC는 선택한 구성과 신선도·인증 정책에 따라 메시지 보호를 다룬다. 모두 같은 범위와 기능을 제공하는 것은 아니다.


### 진단 접근


진단 서비스 권한, 세션·보안 상태, gateway routing, 외부 인터페이스와 rate limit를 확인한다. 연결이 가능하다는 사실과 민감한 서비스를 수행할 권한을 구분한다.


### 키와 신선도


키·인증서의 저장·배포·갱신·폐기, 시간 또는 counter 등 신선도 관리, 재시작·동기화 실패를 검토한다. 소스 코드·브라우저 HTML·로그에 토큰이나 키를 넣지 않는다.


### 검증 관점

- 허용·거부 입력과 접근 권한.
- 메시지 위변조·재전송의 탐지 정책.
- 인증 실패·자원 제한·복구 동작.
- 키·인증서 수명과 설정 오류.
- 보안 적용 전후의 지연·부하.

검증은 승인된 시험 환경에서 수행한다. ISO/SAE 21434의 위협 분석·위험 관리 관점과 실제 프로젝트 보안 계획을 연결해 검토한다.


### 실습: 접근 정책과 비밀값 점검


진단 포트·외부 인터페이스·gateway 경로를 표로 만들고 역할별 허용 서비스를 정의한다. 정상 인증, 권한 부족, 잘못된 입력, 세션 만료를 승인된 시험 환경에서 구분해 확인한다.


공개 코드·HTML·설정·로그에 개인 토큰과 키를 넣지 않는다. CI에서는 서버 측 secret binding을 사용하고, 클라이언트에는 공개 정보만 전달한다.


### 시험 기록 예제


재전송 시험은 정상 메시지 캡처 → 같은 메시지 재입력 → 신선도 정책의 수락·거부 확인 → 재시작 후 정책 확인으로 구성한다. 허가된 시험 환경과 공개용 재구성 데이터만 사용하며 실제 차량에서 임의 실행하지 않는다.
